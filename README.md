# Kubera Learning 📚

A practical learning laboratory for becoming an **AI engineer and AI-agent builder**.

This repository is not intended to be a giant bookmark dump. It turns high-quality external knowledge into a focused path: **learn → build → test → document → improve**.

## 🎯 Goal

Build the knowledge and practical engineering skills needed to:

- work confidently with Python, Git and GitHub;
- understand machine learning, neural networks, transformers and LLMs;
- build RAG systems and evidence-backed knowledge tools;
- build AI agents with tools, memory and human approval;
- evaluate AI systems instead of trusting demos;
- run local/private AI and route between models;
- deploy observable, reliable AI applications;
- apply the strongest ideas to **KUBERA AGENT OS**.

## 🧭 Start here

➡️ **[KUBERA AI Engineer Roadmap](docs/AI_ENGINEER_ROADMAP.md)**

The roadmap organizes the learning path into practical stages, from Python and neural-network foundations through LLM engineering, RAG, agents, protocols, evals, local AI, durable execution and production systems.

| Track | What it develops | Practical outcome |

## 🔥 Curated external knowledge

A major reference is [awesome-artificial-intelligence](https://github.com/owainlewis/awesome-artificial-intelligence), an actively maintained curated collection covering AI foundations, LLM engineering, agent frameworks, retrieval, evals, deployment and coding agents.

Rather than copying that repository, Kubera Learning selects the parts most relevant to our engineering direction and converts them into build stages and concrete projects. Original authors and canonical sources remain linked directly.

## 📂 Repository structure

- `python-lessons/` — Python scripts and exercises.
- `ai-projects/` — AI experiments and prototypes.
- `web/` — simple websites and deployment experiments.
- `docs/` — learning notes, roadmaps and technical guides.

## 🛠️ Build-first rule

Every important subject should eventually produce something testable:

1. Learn the minimum theory needed.
2. Build a small working version.
3. Test normal and failure cases.
4. Explain what happened in plain language.
5. Record failures and improvements.
6. Reuse successful patterns in a larger project.
